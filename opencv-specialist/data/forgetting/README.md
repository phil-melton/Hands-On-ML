# Forgetting slice: 300 EvalPlus MBPP+ problems (evaluation only, never training data)

Built 2026-10-22 for success criterion 3 (LOGBOOK, frozen 2026-10-22; PLAN.md §6): the fine-tuned specialist may lose at most 3 points of
pass@1 on a general Python slice, measured paired on the shipped GGUF against the same base. Project rule 5: every dataset used is recorded here with its
license. The harness is `bakeoff/forgetting.py`; tests are `tests/test_forgetting.py`.

## What `mbppplus_slice.jsonl` is

300 rows, one per line, sorted by MBPP id, 4,227,722 bytes, SHA-256 `4820ab7de00c34df1f419ac26c73ba97beff8984c6684cf91023287e0a952af9`. Fields:

| Field | Meaning |
|---|---|
| `task_id`, `mbpp_id` | `"Mbpp/<n>"` and `<n>` (the EvalPlus id) |
| `prompt` | the task text, unchanged (stripped) |
| `entry_point` | the function the tests call, read from the final loop of the test script with `ast` (checked: defined at top level by the reference solution and named in the first original assert) |
| `test_list` | the original MBPP asserts (the first one is shown to the model as the example, as EvalPlus does) |
| `test_imports` | the dataset's `test_imports` (mostly empty, otherwise `import math`; the test scripts import what they need) |
| `test` | the EvalPlus test script, unchanged: `inputs` and `results` literals, an `assertion` helper (float tolerance, set/sorted comparisons) and a loop over all pairs; 3 problems compare against an in-script `ref_func` |
| `reference` | the dataset's `code` (canonical solution), used for the sandbox validation and the tests |
| `source`, `license`, `ngram13_shared` | provenance, license note, and 0 (no 13-gram shared with `replay.jsonl` or `train.jsonl`, by construction) |

`overlap_report.jsonl` (212 KB) has one row per MBPP+ problem (all 378): its status (in slice / pool, not sampled / dropped and why) and, for each of the four
texts checked, the number of 13-grams and the most shared with any one row of each corpus. `build_report.json` has every count below.
`SOURCE_SHA256SUMS.txt` is the download folder's hash list.

## Filters (applied in this order; counts are problems remaining)

| Step | Problems |
|---|---|
| EvalPlus MBPP+ test split | 378 |
| Drop any problem whose text, reference solution or asserts match `cv2`, `opencv`, `image(s)`, `pixel(s)`, `photo`, `picture`, `bitmap`, `grayscale`, `rgb`, `computer vision`, `camera` (the pattern is narrow on purpose: the broader words "color(s)" (Mbpp/74, a pattern-matching task) and "resolution" (Mbpp/725, quotation marks) are not image processing) | 378 (none matched) |
| Drop any problem with a word 13-gram in common with a row of `data/replay/replay.jsonl` (600 rows) or `data/train.jsonl` (2,847 rows) | 375 (**3 dropped**: Mbpp/239, 247, 752) |
| Drop any problem whose reference solution does not pass its own tests through the sandbox path (Mbpp/255: `MemoryError` under the sandbox's 2 GB address-space limit; it needs 3-4 GB even for the reference, so it is excluded rather than the limit raised) | 374 (the pool: 375 references checked, 374 pass) |
| Seeded sample of 300: sort the pool by `sha256("20261022\|<mbpp_id>")`, keep the first 300, sort by id (deterministic on any Python version; `bakeoff.forgetting.select_slice`) | **300** (74 pool problems unused; `build_report.json: pool_not_sampled`) |

### 13-gram overlap (the replay README's caveat, `data/replay/README.md`)

Method: lowercase, tokens are `\w+` runs (punctuation ignored, so this over-detects relative to a whitespace split), word 13-grams. For each MBPP+ problem four texts
were checked against **every row** of both corpora (user and assistant turns of each row, system prompt excluded; streamed row by row): the task text
(285 of 378 problems have at least one 13-gram), the prompt as the model sees it (text + entry point + first assert; 378), the reference solution (227) and the original
asserts (285). A problem is dropped if any text shares any 13-gram with any row.

Result: **0 of 378 task texts, 0 prompts as shown and 0 assert lists overlap**; 3 reference solutions do, all generic dynamic-programming code
shared with replay rows (these rows are in both `replay.jsonl` and, for the 288 replay rows that went into the training mix, `train.jsonl`):

| Problem | What it is | 13-grams shared | Rows |
|---|---|---|---|
| Mbpp/239 | count sequences, each element >= twice the previous (DP table) | 11 of 59 | replay `58425ecc...`, 4 replay rows; train `replay/7d41832cef71`, 3 rows |
| Mbpp/247 | longest palindromic subsequence (DP table) | 1 of 53 | replay `aa4d596b...`; train `replay/165fa64a03f0` |
| Mbpp/752 | nth Jacobsthal number (DP recurrence) | 7 of 20 | replay `0aa1eb8b...` (that row is not in `train.jsonl`) |

For information only (not used to drop): at 8-grams, 5 problem texts and 19 reference solutions share an 8-gram with some row (common phrasing such as
"write a function that takes a list of").

The test `test_the_slice_shares_no_13gram_with_the_replay_set_or_the_training_set` re-runs this scan on the current `replay.jsonl` and `train.jsonl`;
if a rebuilt training set overlaps the slice, it fails: rerun `build_slice.py`.

## How it was built (rebuild)

```
# 1. parquet -> JSONL (train venv has pyarrow; data only)
~/venvs/train/bin/python -I ~/opencv-expert/scratch/forgetting/parquet_to_jsonl.py <parquet> raw.jsonl
# 2. filters, overlap scan, sandbox validation of the references, selection (cv5 venv; takes ~35 s, 2 workers)
~/venvs/cv5/bin/python -I ~/opencv-expert/scratch/forgetting/build_slice.py raw.jsonl <out_dir> --n 300 --workers 2
```
`--n 374` would keep the whole pool (about 25 % more problems, a tighter interval, 25 % more generation time).

## Caveats

- Qwen3.5's pretraining almost surely saw MBPP (public since 2021), so absolute pass@1 is inflated. The criterion is the paired before/after difference, in which shared
  contamination cancels (PLAN.md §6); this slice is not a leaderboard number.
- Short MBPP prompts: the model is also told the function name and shown the first original assert, as EvalPlus does for chat models. Greedy decoding, one reply per problem.
- 300 problems resolve a paired difference to about +-4 points at 95 % (the width depends on how many problems the two models answer differently); the report states whether the interval excludes a drop above 3 points.
- The pool problems that are not in the slice are listed in `build_report.json` and can serve as a second, disjoint check if the first is borderline.
